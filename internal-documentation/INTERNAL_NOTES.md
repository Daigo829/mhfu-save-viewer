# MHFU Save Viewer — internal notes

Technical reference for the viewer. Not part of the website; nothing here is
shipped in `uploads/docs/`. Everything below is what the code in `app.js` and
`decryptor.js` actually reads, as of **v0.9**.

All offsets are into a **decrypted character save**: 438,528 bytes (`0x6B100`).
All multi-byte values are **little-endian**. The viewer is read-only — it never
writes, re-encrypts, or downloads.

Provenance note: the pre-v0.9 offsets below are transcribed from the shipping
code, not from their original ground-truth files (those are not in this
project). The v0.9 award offsets carry their proofs, which are in
`uploads/v0.9/`.

---

## 1. File layout and decryption

`MHP2NDG.BIN` carries two encryption layers.

| Stage | Detail |
|---|---|
| PSP layer | AES-128-CBC, IV = 16 zero bytes, region key auto-detected. 1,483,024 → 1,483,008 B |
| Game layer | Capcom substitution + rolling XOR (the QuickBMS `MHFU_SaveDecrypter.bms` logic) |
| Region oracle | salted SHA-1 stored in the decrypted body; US/EU tried first, then JP |
| Slot cut | `character1/2/3.sav` at `0x1000` / `0x6C100` / `0xD7200`, 438,528 B each |

US/EU is verified byte-for-byte against known-good decrypted saves. The JP path
uses the same method but has not been confirmed against a JP-region BIN.

A dropped file is routed purely by size: 438,528 → load directly;
1,483,024 or 1,483,008 → decrypt, then show the slot picker.

## 2. Monster arrays

Four parallel arrays of **90 u16 slots**, indexed by internal monster ID (1-based):

| Array | Base | Element |
|---|---|---|
| Captured | `0x402C` | `0x402C + (id-1)*2` |
| Largest size % | `0x40E0` | `0x40E0 + (id-1)*2` |
| Smallest size % | `0x4194` | `0x4194 + (id-1)*2` |
| Slain | `0x4248` | `0x4248 + (id-1)*2` |

Six slots are unused; one counter at `0x4282` is unidentified. The full 90-slot
map is the `SLOTS` table in `app.js` and is rendered live by the Advanced tab.

Displayed size in cm = `base_cm × percent / 100`. Base sizes and crown
thresholds live per-row in the `DATA` table (`b`, `mi` small-crown %,
`kg` big-crown %, `gmn`/`gmx` absolute game min/max %).

Crown test, per form:

```
small crown : recorded_smallest% <= mi
big crown   : recorded_largest%  >= kg
```

`gmn`/`gmx` are the absolute extremes, shown only on the Monsters tab. They are
**not** crown thresholds and must never be used for the crown awards.

Five ranges were widened past the ryin77 guide to match a verified 3,600 h save:
Tigrex max 138, Teostra max 140, Kushala Daora max 138, Diablos max 154, Yian
Garuga (One-Eyed) min 86.

### Guild-card display cache

`0x67408`, per base species: `[u16 ?][u16 hunted][u16 max×10][u16 min×10]`.
Read for the Monsters-tab family totals. Regenerated by the game.

## 3. Hunter / quests / equipment offsets

| Field | Offset | Type |
|---|---|---|
| Character name | `0x0000` | UTF-16LE, ≤10 chars, NUL-terminated |
| Playtime | `0x03FC8` | u32, total seconds |
| Pokke Points | `0x69248` | u32 (caps 9,999,999) |
| Guild Points | `0x6924C` | u32 |
| Zenny | `0x69250` | u32 |
| Guild-card greeting | `0x672EC` | UTF-16LE, may be fullwidth (fold `0xFF01–0xFF5E` → ASCII, `0x3000` → space) |
| Weapon usage | `0x678E0` | 11 × u16, internal order |
| Felyne comrades | `0x67E48` | 9 records, stride `0x40` |

Felyne record: `+0x03` level (stored −1), `+0x04` u16 attack, `+0x06` u16
defense, `+0x18` first-leader name (UTF-16LE, 16 B).

Weapon array order ≠ on-screen bar order.
`screen[i] = array[WPN_PERM[i]]`, `WPN_PERM = [0,7,4,6,2,8,3,9,5,1,10]`.

Quest counters (save order):

| Counter | Offset | Width |
|---|---|---|
| Chief's Quests | `0x672D8` | u16 |
| Guild Hall — Low Rank | `0x672DA` | u16 |
| Guild Hall — High Rank | `0x672DC` | u16 |
| Treasure Quests | `0x672DE` | u16 |
| Training School | `0x672E0` | u16 |
| Nekoht's Quests | `0x672E2` | u16 |
| Guild Hall — G Rank | `0x672E4` | u32 |

On-screen display order is `[0,5,1,2,6,3,4]`.

Equipment box: `0x00A8`, 1000 records × 12 bytes. `+0` non-zero = occupied,
`+1` category (0 legs, 1 head, 2 body, 3 arms, 4 waist, 5 blademaster weapon,
6 gunner weapon), `+2` u16 item ID. Category > 6 is treated as corrupt/cheated
and skipped. IDs are resolved against `equipment_full_table.csv`, with an
embedded fallback table (255 G-weapons, 532 rarity IDs) so `file://` opens work
when the fetch is blocked.

## 4. Awards (v0.9)

### 4.1 Earned-flag bitset — `0x67400`

6 bytes = 48 bits, LSB-first, byte-major. Bit `i` = the i-th award in
guild-card order, `1A` = bit 0 … `2X` = bit 47.

```
earned(i) = (save[0x67400 + (i>>3)] >> (i & 7)) & 1
```

Verified cell-for-cell against five saves: Daigo-JP and Daigo-US
(`FF FF FF FF FF FF`, 48), Umehara-US (`00`×6, 0), vandemtr-JP
(`1F 08 1C 00 00 00`, 9), Mariya-US (`FF C7 0F F7 30 01`, 27).
Region-independent.

**It is a regenerated cache, not the master store.** Proven live: zeroing it
emptied Guild Card page 6, and completing one Low-Rank 3★ gathering quest
restored 15 awards at once — all of them ones the save genuinely qualifies for.
A static cross-save search found no second region encoding the award set, so
awards are recomputed per-award from heterogeneous sources.

Consequences: writing here grants nothing (the next quest clear overwrites it),
it is an excellent read source (it is the game's own verdict), and it can be
used as an oracle — set the underlying data, clear one quest, read what the game
concludes.

### 4.2 Completion rule

```
complete = requirement_met OR earned_bit
```

Awards are monotonic — once earned, permanent, with no in-game way to lose one.
So a set bit can legitimately exceed current reconstructed progress, and must
never be un-marked by it. Canonical case: 2V was earned years ago, the box has
since been sold down to ~43 G-weapons; the bar reads 43/50 and the award is
still complete. That is **not** a cheated-save signal.

The OR also covers cache lag: an award just earned whose cache line has not
regenerated is still caught by the requirement side.

Future intent (not built): a per-award rule, with quest awards using AND and
equipment awards using OR.

### 4.4 1G / 1H — crowns

Bits: 1G `0x67400 & 0x40`, 1H `0x67400 & 0x80`.

Aggregated **per monster, any form counts** — the game shows one small and one
big crown icon per base-species and does not care which form earned it.
Thresholds are per-form, so each form is tested against its own `mi`/`kg`, then
OR'd across the family. Denominator = families with `sz = 1`.

**Accepted, not proven.** Unlike 1O/1P these were never run through the
recompute oracle. The user accepted the viewer's existing crown thresholds as
the award's thresholds and the has-size set as the qualifying set. The earned
bit contains the risk: a wrong denominator can only mis-state the X/N, never the
complete/not verdict.

### 4.5 1O Rare Species Report

Bit `0x67401 & 0x40`. Rule: hunt (slain **or** captured ≥ 1) each of a
16-variant set. Kills alone suffice; one per variant is enough; base species are
irrelevant.

The 16: Pink Rathian, Gold Rathian, Azure Rathalos, Silver Rathalos, Blue Yian
Kut-Ku, Purple Gypceros, Red Khezu, Black Gravios, White Monoblos, Black
Diablos, Green Plesioth, Plum Daimyo Hermitaur, Terra Shogun Ceanataur, Emerald
Congalala, Copper Blangonga, **Ashen Lao-Shan Lung**.

**Do not "fix" the asymmetry.** Golden Rajang, Rusted Kushala Daora and Yian
Garuga (One-Eyed) are proven NOT required and are deliberately absent; Ashen
Lao-Shan Lung is proven required even though Rusted Kushala — its structural
twin — is not. No clean rule explains the split. The three Fatalis colours are
not part of 1O at all.

Proven by leave-one-out on a cheated save: remove Ashen → award lost; hunt a
real Ashen → award regained. Rusted Kushala and One-Eyed Garuga removed → award
still granted. The other 15 are untested individually but sit inside a
proven-sufficient set, so listing them is safe.

### 4.6 1P Ecology Research Report

Bit `0x67401 & 0x80`. Rule: all 43 capturable monsters with captured ≥ 1 in the
`0x402C` array. **Captures only** — kills do not count.

The 43 offsets are the `CAP43` array in `app.js`.

**One-Horned Diablos is not a separate entry.** It has no slot of its own and
shares base Diablos (`0x4048`); either satisfies 1P. Counting 44 would produce a
permanently unsatisfiable row. **One-Ear Garuga** (One-Eyed, `0x40C8`) *does*
have its own slot and *is* separately required. Black Diablos (`0x4082`) is a
genuine subspecies, unrelated to the one-horn.

Fully proven: the 43-set derived from two award-complete saves (JP and US,
identical), then confirmed in-game — 42/43 with Diablos missing did not grant,
43/43 did, via both a real one-horn capture and a hex edit.

### 4.7 Still unmapped — 38 of 48

Everything except {1E, 1F, 2M, 2Q, 2V, 2W} and {1G, 1H, 1O, 1P}. Needs the
quest-clear bitfield, per-map counters, training matrices, and renovation flags.

## 5. Open items

- 1G/1H not oracle-proven: the qualifying set and the gold-crown tier are
  accepted, not tested.
- 15 of 1O's 16 variants are untested for individual necessity (the set is
  proven sufficient, so the tab can never show a false complete).
- 42 of 1P's 43 are untested individually; membership rests on the two
  award-complete saves plus the guide.
- JP decryption path unconfirmed against a real JP BIN.
- `0x4282` unidentified.
- Cheated-save detection is a separate, deferred system. A set bit exceeding
  reconstructed progress is not evidence of one.
